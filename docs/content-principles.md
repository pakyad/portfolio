# Content Principles — Muhammad Iyad

## Editorial Voice

First person, plain, relaxed but matured. The site reads like an engineer documenting their own work, not a resume and not an ad.

- Short sentences. Contractions welcome.
- Specific facts over claims: name the stack, name the trade-off, name what broke.
- Dry humor is allowed; superlatives are not.
- No "thoughtful digital products", "seamless", "production-minded", or repeated catchphrases across pages.
- No identical scaffolds between projects — each case study has its own outcome structure.

## Positioning

One intro sentence under the hero name: who I am, where I am, what I build end to end.

## Project Storytelling Structure

Fixed sequence, unique copy per project:

1. **Title / Status chip / Role / Year** — the facts.
2. **Thesis** — one sentence on what the system is.
3. **Problem + Key constraint** — specific to context, never generic industry filler.
4. **Screenshots** — real captures where they exist; no fabricated UI art for missing assets (unavailable projects go text-only with an honest note).
5. **Constraints → Decisions** — numbered trace rows plus system layer breakdowns.
6. **What broke** — honest failure stories, each with its fix.
7. **What I learned** — structured `{ label, body }` sections in `src/content/projects.ts`; 2–3 per project, distinct labels per project, no shared template.

## Rules

- No invented metrics, testimonials, awards, or client logos.
- Every feature listed must be a verifiable capability.
- Availability is stated honestly: live projects get Live tags; paused/offline projects get an "Unavailable" status chip and note instead of pretending.
- Placeholder entries (More builds) are visibly marked until replaced with real sites.

## Contact

Availability statement + horizontal links: email (primary, gold), GitHub, LinkedIn, WhatsApp. No contact forms.

## Forbidden Content Patterns

No "About Me" headings, no skills heatmaps, no emoji in content, no exclamation marks or questions in headings, no statistics without methodology.
